# Postprocessing

SkelHub postprocessing turns skeleton outputs into graph and vessel-feature
representations.

## Overview

The postprocessing package contains two user-facing modules:

- `skelhub.postprocessing.graphgen` converts a binary vessel skeleton NIfTI
  volume into a Voreen-style proto-graph in GraphML format. Graph nodes record
  branch/end points, and graph edges record ordered centerline voxels.
- `skelhub.postprocessing.feature` extracts branch and node features from a
  binary vessel foreground volume, its skeleton volume, and compatible
  GraphML. It writes one CSV for edge features and one CSV for node positions.

These workflows are adapted from vessel graph generation and feature
extraction implemented in Voreen [1]. SkelHub provides a Python/CLI implementation
with its documented graph input and dual-space measurement conventions.

A typical workflow is:

```text
vessel foreground -> vessel skeleton -> GraphML graph -> edge/node feature CSVs
```

`feature` accepts GraphML generated by `skelhub graphgen` or cleaned graph
output generated by `skelhub run --algorithm laplacian --graph_output ...`.
For feature calculation, stored GraphML centerline paths define the branch
geometry.

The edge CSV includes branch length, radius statistics, curveness, and endpoint
degrees. Base feature columns use voxel coordinates. Additional
`*_image_<unit>` columns use the foreground NIfTI header voxel spacing. The
node CSV records graph node IDs, voxel positions, and node degrees.

## Graph Generation

### Method

- Load the skeleton NIfTI and reject an empty or non-3D volume. Voxels greater
  than zero are treated as skeleton foreground.
- Count each foreground voxel's 26-neighbors: at most one makes an endpoint,
  two makes a regular voxel, and three or more makes a branch voxel.
- Form 26-connected components for each class and order every regular component
  as a centerline path using voxel adjacency.
- Create one node per endpoint or branch component, then connect neighboring
  nodes through regular paths. Closed regular components become synthetic
  self-loops; an otherwise-isolated node touching another node receives an
  empty-path edge.
- Write an undirected GraphML graph. Nodes store their supporting voxels, mean
  voxel position, affine-transformed world position, kind, and border status;
  edges store ordered centerline voxels and world-space points.

### Usage

Generate GraphML from a binary skeleton NIfTI:

```bash
skelhub graphgen \
  --input skeleton.nii.gz \
  --output vessel.graphml \
  --verbose
```

Inputs and outputs:

- Input: a binary 3D skeleton NIfTI volume.
- Output: a GraphML graph containing node positions and ordered edge
  `centerline_voxels`.

The short flag form is also supported:

```bash
skelhub graphgen -i skeleton.nii.gz -o vessel.graphml
```

## Feature Extraction

### Method

- Load binary 3D foreground and skeleton volumes; require equal shapes and
  affines, and require every skeleton voxel to lie inside the foreground.
- Parse and validate graphgen or Laplacian GraphML IDs, node voxel positions,
  and edge `centerline_voxels`. These paths remain authoritative; path voxels
  outside the supplied skeleton produce a warning.
- Run the measurements in voxel space and again using the foreground NIfTI
  voxel sizes. In each space, assign foreground voxels to their nearest edge
  path, remove assigned components not anchored to that path, and flood any
  resulting unlabeled regions from neighboring assignments.
- For each edge, sum the polyline distance from its first node through its
  centerline to its second node. Curveness is this length divided by endpoint
  distance.
- Estimate radius statistics from assigned vessel-surface distances to each
  centerline sample, with a half-voxel correction (or half the mean voxel size
  in image space). Empty paths yield `NaN` radii.
- Write edge measurements and endpoint degrees to one CSV, and node voxel
  positions and degrees to another.

### Usage

Extract Voreen-style vessel branch and node features:

```bash
skelhub feature \
  --foreground vessels.nii.gz \
  --skeleton skeleton.nii.gz \
  --graph vessel.graphml \
  --edge-output edge_features.csv \
  --node-output node_features.csv \
  --verbose
```

Inputs:

- `--foreground`: binary vessel segmentation NIfTI.
- `--skeleton`: binary vessel skeleton NIfTI associated with the foreground.
- `--graph`: compatible GraphML from `graphgen` or Laplacian cleaned graph
  output.

Outputs:

- `--edge-output`: CSV containing edge IDs, endpoint IDs, lengths, radius
  statistics, curveness, endpoint degrees, and image-space feature columns.
- `--node-output`: CSV containing node IDs, voxel positions, and node degrees.

To use cleaned Laplacian graph output directly:

```bash
skelhub run \
  --algorithm laplacian \
  --input vessels.nii.gz \
  --output skeleton.nii.gz \
  --graph_output vessel.graphml

skelhub feature \
  --foreground vessels.nii.gz \
  --skeleton skeleton.nii.gz \
  --graph vessel.graphml \
  --edge-output edge_features.csv \
  --node-output node_features.csv
```

For the Python entrypoints, see [Python API](API.md). For field-level output
details, see [Structured Output](StructuredOutput.md).
